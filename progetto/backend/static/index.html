Pipeline multi-agente didattica

              
Trasforma un libro o un PDF in un corso microlearning completo

              
Sei agenti specializzati lavorano in sequenza: acquisizione, conversione, pianificazione, segmentazione, validazione e infine il Deep Agent che progetta lezioni e quiz in italiano.

Carica e dimentica

              
PDF, Word o Markdown: la pipeline crea una cartella dedicata in workspace/ con tutti gli artefatti intermedi e il corso finale.

            

            

              
Riprendi da qualsiasi step

              
Ogni fase salva file JSON e markdown. Puoi interrompere, correggere e ripartire senza rifare tutto dall'inizio.

            

            

              
Deep Agent autoincrementale

              
L'ultimo agente esplora il materiale, usa script e note condivise e può arricchire la propria libreria tra una run e l'altra.

    4.

      Come funziona l'applicazione
      
            
      Un supervisore orchestra sei agenti specializzati. Ogni agente legge e scrive file nel workspace del corso; puoi riprendere da qualsiasi step. Con più documenti, il planning li fonde in un unico piano corpus prima di segmentare e validare.
      
          
      

          
      
            
      Flusso della pipeline (singolo documento)
      
            
      
              
      Acquisizione
      0–8%
      
              
      
              
      Document
      8–52%
      
              
      
              
      Planning
      52–65%
      
              
      
              
      Segmentation
      65–78%
      
              
      
              
      Validation
      78–92%
      
              
      
              
      Microlearning
      92–100% · Deep Agent
      
            
      
            
      Le percentuali sono calcolate in agent_logging.py e compaiono in activity.log come [ 52.0%] messaggio. Output finale: reports/microlearning_course.json.
      
          
      

          
      
            
      Corso multi-libro (corpus)
      
            
      Se carichi più PDF con lo stesso course_id, la pipeline elabora ogni libro (document + planning per source_id), poi esegue una fase aggiuntiva planning_corpus:
      
            
      
              
      
                PDF A
                →
                plan A
              
      
              
      
                PDF B
                →
                plan B
              
      
              
      
                ↓
                Embedding + similarità
                →
                corso_plan.json
              
      
              
      
                Segmentation corpus
                →
                Validation
                →
                Microlearning
              
      
            
      
            
        
              
      • corpus_fusion.py — accoppia capitoli simili tra libri (similarità coseno su embedding OpenRouter).
        • 
              
      • corso_plan.json — piano unificato con lezioni «Integrazione: …» quando due fonti trattano lo stesso argomento.
        • 
              
      • corpus_embeddings_cache.json — cache degli embedding per non ricalcolarli a ogni run.
        • 
            
      
          
      

          
      
            
      Embedding semantici — come si allineano i libri
      
            
      La fusione corpus non confronta solo i titoli dei capitoli: ogni punto di taglio diventa un vettore numerico che cattura il significato del testo.
      
            
      
              
      
                1 · Snippet
                Estratto testo sezione
      ~1000 caratteri      
              
      
              →
              
      
                2 · OpenRouter
                /v1/embeddings
      text-embedding-3-small      
              
      
              →
              
      
                3 · Vettore
                [0.12, −0.04, …]
              
      
              →
              
      
                4 · Similarità
                coseno ≥ 0.28
      → Integrazione      
              
      
            
      
            
        
              
      • embedding_client.py — client OpenRouter, batch da 48, cache su disco con hash SHA-256 del testo.
        • 
              
      • corpus_fusion.py — per ogni punto del libro A cerca il miglior match nel libro B; sopra soglia crea una lezione integrata con segmenti da entrambe le fonti.
        • 
              
      • Configurazione in .env: OPENROUTER_EMBEDDING_MODEL, CORPUS_EMBEDDING_MIN_SIMILARITY, CORPUS_EMBEDDING_SNIPPET_CHARS, CORPUS_EMBEDDING_BATCH_SIZE.
        • 
            
      
            
      Serve OPENROUTER_API_KEY anche se il modello chat usa Groq — gli embedding passano sempre da OpenRouter.
      
          
      

          
      Gli agenti e cosa fanno
      
          
      
            
      
              01
              
      Acquisition Agent
      
              
      Riceve il file caricato (PDF, Word, …), lo salva in uploads/ e crea i metadati iniziali: tipo file, lingua, se serve OCR.
      
              
      Output: file in uploads + SourceInput
      
            
      
            
      
              02
              
      Document Agent
      
              
      Converte il documento in Markdown, pulisce il testo, crea chunk per l'LLM, analizza qualità e struttura del documento con intelligenza artificiale.
      
              
      Output: markdown in sources/, chunk, report qualità
      
            
      
            
      
              03
              
      Planning Agent
      
              
      Analizza titoli e sezioni, stima carico cognitivo e durata, definisce i punti di taglio. Con più libri esegue planning_corpus e fusione semantica.
      
              
      Output: *_plan.json, corso_plan.json
      
            
      
            
      
              04
              
      Segmentation Agent
      
              
      Esegue i tagli fisici sul markdown secondo il piano, producendo moduli grezzi con testo, token stimati e riferimenti alle righe.
      
              
      Output: *_raw_modules.json
      
            
      
            
      
              05
              
      Validation Agent
      
              
      Controlla coerenza logica, propedeuticità e prerequisiti. Regole locali + LLM opzionale sui moduli dubbi.
      
              
      Output: *_validated_modules.json
      
            
      
            
      
              06
              
      Microlearning Agent (Deep Agent)
      
              
      Agente autonomo basato su LangChain Deep Agents: esplora il workspace, legge note e script, scrive lezioni in italiano e quiz con obiettivi e attività pratiche.
      
              
      Output: microlearning_course.json
      
            
      
          
      

          
      
            
      Filesystem virtuale del Deep Agent
      
            
      L'agente microlearning non vede il disco come un path assoluto Linux. Il corso corrente è montato su route virtuali:
      
            
      
              
      
                
      Lettura (corso)
      
                
        
                  
      • /sources/ — markdown puliti
        • 
                  
      • /reports/ — piani, qualità, corso_plan.json
        • 
                  
      • /modules/ — moduli validati
        • 
                  
      • /chunks/, /uploads/
        • 
                
      
              
      
              
      
                
      Scrittura (home globale)
      
                
        
                  
      • /notes/ — playbook condiviso
        • 
                  
      • /scripts/ — helper riusabili
        • 
                  
      • /memory/ — miglioramenti tra run
        • 
                
      
              
      
            
      
            
      Usa sempre read_file("/reports/corso_plan.json") — non path assoluti tipo /home/.../workspace/.... I comandi execute partono dalla cwd del sandbox: python3 -c "open('/reports/...')" spesso fallisce anche se read_file funziona.
      
            
      Ordine di lettura consigliato per l'agente: percorsi_filesystem.md → workflow_microlearning.md → struttura_lezione.md in agent_shared/notes/.
      
          
      

          
      
            
      Perché il Deep Agent è "autoincrementale"
      
            
      A differenza degli altri agenti (pipeline fissa con input/output definiti), il Deep Agent ha una libreria globale condivisa in agent_shared/ che evolve tra le run:
      
            
        
              
      • Note (agent_shared/notes/): linee guida su struttura lezione, quiz, workflow e percorsi filesystem. L'agente le consulta mentre progetta il corso.
        • 
              
      • Script (agent_shared/scripts/): tool riusabili (elenco sorgenti, grep, estrazione titoli) che l'agente può eseguire sul corso corrente.
        • 
              
      • Memoria (agent_shared/memory/): appunti di miglioramento che persistono tra un corso e l'altro.
        • 
            
      
            
      Il materiale del corso (sources/, reports/, …) è montato in sola lettura; la home condivisa è in scrittura. Così l'agente può arricchire script e documentazione senza modificare i dati del corso, e ogni run successiva beneficia di quanto appreso o aggiunto in precedenza.
      
            
      Nella sezione Pipeline, il pannello "Deep Agent (live)" mostra tool call e risposte del modello in tempo reale durante questo step.
      
          
      

          
      
            
      
              
      Struttura workspace
      
              
      workspace/{course_id}/
├── course.json       metadati + elenco sources (corpus)
├── activity.log      log narrativo con [NN.N%]
├── uploads/          file caricati
├── sources/          markdown (raw, clean, finale)
├── chunks/           testo per LLM
├── reports/          piani, qualità, corso_plan, microlearning
├── modules/          moduli grezzi e validati (corso_* se corpus)
└── reports/corpus_embeddings_cache.json
